Three levels

Three levels of getting started with code

There are three ways most of us got started, and each one is a little bigger than the last. Level 1 runs inside your AI chat. Level 2 lives on your own website. Level 3 does work for you behind the scenes, in your Drive. Every level is a good level. The best one is the one that would stretch you a little.

On the day: watch all three happen live, then pick yours.

1

In the chat

A small tool that runs right inside your AI chat: a timer, a picker, a quiz, an oracle. You describe it, the AI writes it, and it appears beside the conversation, working. Nothing to install and nothing to publish.

Live on the day

The Teacher's Lounge Oracle, pasted into a chat from the starters page, then taught a new topic.

Try it

  1. Open the starters and press Play on one. Guess what it does first.
  2. Press Copy for my AI and paste into Gemini (choose Canvas first), Claude, or ChatGPT (switch on Preview when the code appears).
  3. Ask for one change. Then another. Then break it on purpose and tell the AI exactly what you see.

Monday

A timer that knows your bell schedule. A spinner for whose turn it is. A quiz on this week's words. Anything you'd put on the board and press.

2

On your site

A document you already have becomes an interactive page, and you put it on your Google Site with a feature most people never find: Embed code. It looks like part of the site. It is the thing you built.

Live on the day

A department charter goes into Gemini with Canvas on, comes out as an interactive infographic, and lands on a Google Site in about a minute.

Try it

  1. Pick a document you already use: a charter, a syllabus, a handbook page, the norms on the wall. Made-up or your own; just nothing about students. Or start from the Charter Cards or the Syllabus Page, two pages that already work.
  2. Copy the prompt below, paste it into Gemini (Canvas on), Claude, or ChatGPT (Preview on), and paste your document after it.
  3. When it looks right, copy the code. Every tool has a code view or a Copy button for it.
  4. Open your Google Site to edit it. Choose Insert, then Embed, then the Embed code tab. Paste, choose Next, then Insert.
  5. Drag the box to the size you want, and Publish.
Read the prompt

Here is a document my team already uses. Turn it into an interactive infographic as a single HTML page: each section becomes a card that opens when clicked or tapped, the key commitments become a row of badges, in plain language and large type, and it works on a phone. Keep the document's meaning exactly; don't add anything it doesn't say. No outside libraries, images, or fonts. The document is below.

If Sites says the code is too long, ask your AI for a lighter version: fewer sections, less decoration. The page runs in its own sealed box on your site, which is why Sites lets it in.

Monday

A syllabus that opens section by section. A family-handbook page people actually read. A "who to call" card for your department. Anything that's a document now and should be a page.

3

Behind the scenes

A short script does a job for you inside Google Workspace: Apps Script, which is built into every Google account. No screen to look at, just work that gets done. The AI writes it, you paste it, you press Run.

Live on the day

A Drive folder with folders inside it, and a script that reads all of them and writes a Sheet: every document, its type, and a link to open it. A whole curriculum, one search away.

Try it

  1. Ask your AI for the script with the prompt below, or start from ours, further down (the Doc Multiplier is the other one).
  2. Go to script.google.com and choose New project. Delete what's there and paste the script.
  3. Open a folder in Drive. Its ID is the long string at the end of the address, after folders/. Paste it between the quotes at the top of the script.
  4. Press Save, make sure inventory is the chosen function, and press Run.
  5. The first run asks for permission: this script wants to see your Drive and make a Sheet. Read it, then allow. If it says Google hasn't verified the app, that's because you just wrote it: choose Advanced, then go to your project.
  6. Open the Execution log. The link to your new Sheet is there, and the Sheet is in your Drive.
Read the prompt

Write a Google Apps Script that lists every file in one Google Drive folder and all of its subfolders in a new Google Sheet: one row per file, with the folder path, the file's title, its type in plain words (Doc, Sheet, Slides, PDF), its link, and when it last changed. Use only DriveApp and SpreadsheetApp. Put the folder ID in one clearly marked line at the top. Then tell me, in plain language, what the first run will ask permission for and why.

Or start from ours

Read the script 
// Drive inventory: every file in a folder and its subfolders, in a new Google Sheet.
// 1. Paste the folder's ID between the quotes. (Open the folder in Drive: the ID is the long string after folders/ in the address.)
// 2. Choose "inventory" and press Run. The first run asks to see your Drive and make a Sheet. Read it, then allow.
// 3. Open the Execution log for the link to the Sheet.

const FOLDER_ID = "PASTE_THE_FOLDER_ID_HERE";

function inventory() {
  const root = DriveApp.getFolderById(FOLDER_ID);
  const rows = [["Folder", "Title", "Type", "Link", "Last changed"]];
  walk(root, root.getName(), rows);
  const sheet = SpreadsheetApp.create("Inventory: " + root.getName());
  sheet.getActiveSheet().getRange(1, 1, rows.length, rows[0].length).setValues(rows);
  sheet.getActiveSheet().setFrozenRows(1);
  Logger.log((rows.length - 1) + " files listed. Open the inventory: " + sheet.getUrl());
}

// Every file in this folder, then every folder inside it, and so on
function walk(folder, path, rows) {
  const files = folder.getFiles();
  while (files.hasNext()) {
    const file = files.next();
    rows.push([path, file.getName(), kind(file.getMimeType()), file.getUrl(), file.getLastUpdated()]);
  }
  const folders = folder.getFolders();
  while (folders.hasNext()) {
    const sub = folders.next();
    walk(sub, path + " / " + sub.getName(), rows);
  }
}

// A file's type in plain words
function kind(mime) {
  const names = {
    "application/vnd.google-apps.document": "Doc",
    "application/vnd.google-apps.spreadsheet": "Sheet",
    "application/vnd.google-apps.presentation": "Slides",
    "application/vnd.google-apps.form": "Form",
    "application/vnd.google-apps.folder": "Folder",
    "application/pdf": "PDF"
  };
  return names[mime] || mime.replace(/^.*\//, "");
}

A script runs as you

  • Read it before you run it. Ask your AI to explain every line. A line nobody can explain doesn't run.
  • The permission screen is the gate. It names exactly what the script may touch. Read it like a permission slip. Ours asks for Drive and Sheets, because that's its whole job; a script that asks for Gmail to list a folder is asking for too much.
  • Made-up files today. Point it at a folder of practice documents while you're learning. Nothing about real students goes into a script you can't yet explain.
  • Never run a script a stranger sent you, and never share one that touches student data. If script.google.com won't open, your district turned it off, and that's a conversation with your technology director, not a workaround.

Monday

An inventory of a curriculum folder, so the right lesson is one search away. A Sheet that fills in a Doc for every row. A reminder that writes itself on Friday afternoon. Anything you do by hand in Workspace, again and again.
